# 로그인 도입 — 진행 상황과 남은 일

지금 모두와는 **로그인이 없습니다.** 앱을 켠 기기를 그대로 "그 사람"으로 취급합니다.
이걸 로그인/로그아웃이 되는 계정 구조로 바꾸는 작업의 현재 상태와 앞으로의 계획입니다.

**한 줄 요약 — 이메일 로그인이 동작합니다.** 가입·로그인·로그아웃과 "가입해도 기존 데이터가
따라오는" 처리까지 끝났습니다. 남은 것은 **소셜 로그인 4종**과 **메일 발송이 필요한 두 기능**
(이메일 인증, 비밀번호 찾기)입니다.

> 마지막 갱신: 2026-08-20

---

## 1. 왜 바꾸나

지금은 기기에 자동으로 생기는 식별값 하나로 사용자를 구분합니다. 그래서 두 가지 문제가 있습니다.

**① 기기를 바꾸면 데이터가 사라집니다.** 폰을 바꾸거나 앱을 지웠다 깔면 새 사람이 됩니다.
그동안 쓴 후기, 만든 플랜, 저장한 장소가 전부 없어집니다. 되찾을 방법이 없습니다.

**② 안전하지 않습니다.** 그 식별값을 아는 사람은 곧 그 사람이 됩니다. 지금은 유출돼도
"그 기기 하나의 데이터"가 걸리는 정도라 감수하고 있지만, 계정에 여러 기기를 묶기 시작하면
기기 하나가 새면 **계정 전체**(다른 기기에서 쓴 것까지)가 열립니다. 그래서 로그인을 붙일 때
"로그인한 사람은 기기 식별값이 아니라 로그인 상태로 확인한다"는 규칙이 반드시 같이 들어가야 합니다.

---

## 2. 로그인이 붙으면 사용자에게 달라지는 것

| | 지금 | 로그인 이후 |
|---|---|---|
| 폰을 바꿨을 때 | 데이터 전부 사라짐 | 로그인하면 그대로 따라옴 |
| 기기 여러 대 | 각각 남남 | 같은 계정으로 묶임 |
| 가입 전에 쓴 글·플랜 | — | **로그인할 때 계정으로 옮겨옴** (아래 ①) |
| 로그아웃 | — | 데이터는 서버에 남고, 다시 로그인하면 돌아옴 (아래 ②) |
| 로그인 수단 | — | 애플 / 구글 / 카카오. 한 계정에 여러 개 연결 가능 |

### ① "가입했더니 내 플랜이 사라졌다"를 막는 규칙 — **이미 만들어 뒀습니다**

로그인 안 한 상태로 쓴 것들이 로그인하는 순간 계정으로 따라옵니다. 상황별로 이렇게 동작합니다.

| 상황 | 결과 |
|---|---|
| 처음 가입하는 사람 | 지금까지 익명으로 쓴 게 **그대로 그 계정 것이 됩니다** |
| 이미 계정이 있는데, 이 기기에서 익명으로 좀 써봤다 | 익명으로 쓴 것을 **계정으로 합쳐줍니다** |
| 이 기기에서 A 계정으로 쓰다가 B 계정으로 로그인 | **합치지 않습니다.** 계정을 섞는 건 되돌릴 수 없어서 |

두 번째 경우에는 서버가 "합쳤음" 신호를 같이 내려줍니다.
앱에서 **"기존에 작성하신 내용을 가져왔습니다"** 같은 안내를 띄울 수 있습니다.

### ② 로그아웃하면 화면을 비워야 합니다

로그아웃해도 계정과 데이터는 서버에 그대로 남고, 다시 로그인하면 돌아옵니다.
다만 **로그아웃한 기기는 빈 상태에서 새로 시작합니다.** 로그아웃 후 그 기기에서 뭔가를 쓰면
계정과 무관한 새 익명 데이터가 됩니다.

> 앱 화면 설계 시 참고 — 로그아웃 직후 저장 탭·플랜 탭은 **비어 있어야** 합니다.
> 로그아웃했는데 이전 계정 데이터가 남아 보이면 안 됩니다.

## 3. 진행 상황

| | 내용 | 상태 |
|---|---|---|
| 계정을 담을 그릇 | 계정·소셜 연결·기기 정보를 저장할 자리 | ✅ 완료 |
| 데이터 이사 규칙 | 위 ①의 상황별 처리 | ✅ **동작 확인 완료** |
| 기기-계정 연결 | 어느 기기가 어느 계정인지 기록 | ✅ 동작 중 |
| **이메일 가입·로그인·로그아웃** | | ✅ **완료** |
| 로그인 상태 유지 | 한 번 로그인하면 계속 로그인된 상태로 | ✅ 완료 (90일, 쓰는 동안 연장) |
| 기존 기능에 로그인 반영 | 후기·플랜·저장·게시글이 계정을 따르도록 | ✅ 완료 |
| 이메일 인증 | 남의 이메일로 가입하는 것 방지 | ⬜ **메일 발송 필요** |
| 비밀번호 찾기 | | ⬜ **메일 발송 필요** |
| 소셜 로그인 | 애플·구글·카카오·네이버 | ⬜ 미착수 |

서버에서 실제로 확인한 것: 익명으로 저장·글쓰기 → 가입 → 데이터가 계정으로 따라옴 →
다른 기기에서 로그인 → 그 기기의 익명 데이터도 합쳐짐 → 로그아웃하면 화면이 비고 →
다시 로그인하면 전부 돌아옴.

---

## 4. 남은 작업

### ✅ 끝난 것 (0~3단계)

병합 버그 수정 → 로그인 상태 저장소 → 이메일 로그인 창구 → 기존 기능 반영까지 완료됐습니다.
**앱에서 로그인 화면만 붙이면 바로 쓸 수 있는 상태입니다.**

이 시기에는 구버전 앱과 신버전 앱이 함께 돌아갑니다. 구버전은 기기 식별값만 보내고
신버전은 로그인 정보를 보내는데, 서버가 양쪽을 모두 받아줍니다.

### ⬜ 메일 발송이 필요한 두 가지 — **출시 전 필수**

도메인과 메일 발송 수단이 준비되면 바로 붙일 수 있게 코드가 정리돼 있습니다.

| | 없으면 생기는 일 |
|---|---|
| 이메일 인증 | 남의 이메일 주소로도 가입이 됩니다 |
| 비밀번호 찾기 | **비밀번호를 잊으면 계정 복구 방법이 없습니다** |

두 번째가 특히 위험합니다. 이메일 로그인을 열어둔 채로 출시하면 비밀번호를 잊은 사용자를
도울 방법이 아예 없습니다. 아래 셋 중 하나를 선택해야 합니다.

1. 도메인·메일을 먼저 붙이고 출시 *(권장)*
2. 이메일 로그인을 감추고 소셜 로그인만 먼저 열기 *(소셜은 비밀번호가 없어 이 문제가 없습니다)*
3. 이메일 로그인을 베타로만 열기

### ⬜ 소셜 로그인 4종

애플·구글·카카오·네이버. **로그인 이후의 처리(데이터 이사·기기 연결·로그인 유지)는
이미 만들어 둔 것을 그대로 씁니다.** 각 회사의 로그인 검증 부분만 새로 붙이면 됩니다.

> iOS는 다른 소셜 로그인을 제공하면 **애플 로그인도 반드시 함께** 제공해야 심사를 통과합니다.

### ⬜ 마지막 정리 (구버전 앱 사용자가 빠진 뒤)

예전 방식(기기 식별값만으로 접근)을 걷어냅니다. 이게 남아 있는 동안은 §1의 ② 보안 문제가
완전히 닫히지 않습니다. 구버전 앱 비중을 보고 시점을 정합니다.

## 5. 기획 결정이 필요한 것

### ① 회원 탈퇴하면 남긴 글은 어떻게 되나 — **가장 먼저 정해야 합니다**

지금 구조에는 **탈퇴 기능 자체가 없고**, 그냥 만들면 두 가지가 서로 다르게 동작합니다.

| 그 사람이 남긴 것 | 지금 구조에서의 결과 |
|---|---|
| 게시글·댓글·플랜·저장 | **함께 삭제됩니다** — 댓글 대화에 구멍이 납니다 |
| **장소 후기** | 삭제가 **막혀서 탈퇴 자체가 실패합니다** |

후기만 다르게 걸려 있어서, 아무것도 정하지 않고 탈퇴를 붙이면 "후기를 한 번이라도 쓴 사람은
탈퇴가 안 되는" 상태가 됩니다.

일반적으로는 **글은 남기고 작성자만 "알 수 없음"으로 바꾸는** 쪽을 씁니다.
개발 쪽 권장도 이쪽이고, 위 불일치도 한 번에 정리됩니다.
다만 개인정보 처리방침과 엮이는 문제라 기획·법무 확인이 필요합니다.

### ② 이메일 로그인을 언제 열 것인가

이메일 가입·로그인은 **이미 동작합니다.** 다만 §4에서 적었듯 비밀번호 찾기가 없어서,
메일 발송을 붙이기 전에 그대로 열면 비밀번호를 잊은 사용자를 도울 수 없습니다.

> 참고 — 소셜 로그인은 비밀번호가 없어 이 문제가 없습니다. 소셜만 먼저 여는 선택지가 있습니다.

### ③ 로그인 안 해도 쓸 수 있는 범위

지금은 로그인 없이 다 됩니다. 로그인이 생기면 **후기 작성·플랜 저장 등을 로그인 필수로 할지,
아니면 지금처럼 익명도 허용할지** 정해야 합니다.
익명 허용은 기술적으로 이미 되고, 로그인 필수로 막는 건 나중에도 바꿀 수 있습니다.

### ④ 닉네임 중복 허용 여부

지금은 같은 닉네임을 여러 명이 쓸 수 있습니다. 막을 거면 "이미 사용 중인 닉네임입니다" 화면과
기존 중복 사용자 처리 방안이 필요합니다.

## 6. 알아두실 점

- **기기 1대 = 계정 1개(동시에).** 한 폰에서 두 계정을 동시에 유지하는 건 안 됩니다.
  계정 전환은 로그아웃 후 로그인입니다.
- **이 작업이 앱 화면에 요구하는 것**은 로그인/로그아웃 화면, 로그아웃 후 화면 비우기,
  "기존 내용을 가져왔습니다" 안내 세 가지입니다.
- **사용자 데이터는 되돌릴 수 없습니다.** 관광 데이터와 달리 후기·플랜은 서버에만 있고
  다시 만들어낼 수 없어서, 4단계의 정리 작업은 백업 후에 진행합니다.
