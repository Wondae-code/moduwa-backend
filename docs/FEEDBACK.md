# 피드백 — 설계

앱에서 의견·오류·정보 정정을 보내는 기능입니다. **로그인하지 않아도 보낼 수 있습니다.**

> 상태: 서버 구현 완료 · 앱 미착수 · 마지막 갱신: 2026-10-10

---

## 1. 정해진 것

| 항목 | 결정 |
|---|---|
| 로그인 | 필요 없음. 로그인했으면 계정이 함께 기록된다 |
| 열리는 곳(카테고리) | 문의하기 · 장소 상세 · 여행 상세, 세 곳 |
| 본문 | 필수, 500자 이하 |
| 답장 이메일 | **선택** (세 카테고리 모두) |
| 기기 정보 | 앱이 **보내는 순간에만** 모아서 피드백에 함께 싣는다. 다른 API 요청에는 붙이지 않는다 |
| 사진 첨부 | **없음** |

## 2. 저장하는 것

| 칼럼 | 타입 | 내용 |
|---|---|---|
| `id` | bigserial | 접수 번호 |
| `author_id` | bigint, 비어도 됨 | 로그인 상태면 세션의 계정. 비로그인이면 비운다 |
| `device_id` | text, 비어도 됨 | 앱이 만든 기기 UUID. **묶어 보기 용도로만** 쓴다(아래 ⚠️) |
| `category` | text | `inquiry`(문의하기) · `place`(장소 상세) · `plan`(여행 상세) |
| `target_id` | text, 비어도 됨 | `place` → contentId, `plan` → 플랜 id. `inquiry` 는 비운다 |
| `body` | text | 본문 |
| `reply_email` | text, 비어도 됨 | 답장 주소 |
| `client` | jsonb | 앱이 보낸 기기 정보 객체 그대로 |
| `status` | text | `new` → `answered` → `closed` (운영 화면에서 바꾼다) |
| `created_at` | timestamptz | |

- **`category` 는 DB 제약(CHECK)으로 묶지 않는다.** 라우트가 허용 목록으로 막는다 — 신고 사유(047)와
  같은 판단이고, 카테고리를 늘릴 때 서버 배포를 기다리지 않게 한다.
- **`client` 는 키별로 검사하지 않는다.** 앱이 항목을 늘려도 서버를 고치지 않는다. 대신 크기 상한
  (2KB)은 둔다 — 비로그인도 보낼 수 있는 칸이라 상한이 없으면 아무거나 무한정 쌓인다.
  운영에서는 `client->>'appVersion'` 처럼 꺼내 본다.
- **`target_id` 는 형식만 보고 존재는 확인하지 않는다.** 그 사이 플랜이 지워졌다고 피드백이 실패하면
  제보를 잃는다. 비로그인 사용자의 플랜은 서버에 없으므로 `plan` 이어도 비어 있을 수 있다.

> ⚠️ **`device_id` 는 신원이 아니다.** "같은 기기에서 온 피드백 묶어 보기"와 도배 막기에만 쓴다.
> 이 값으로 "내 피드백 보기"·수정·삭제를 허용하면 안 된다 — 남의 deviceId 를 실어 보내면 그 사람이
> 되는 구멍이 다시 열린다(accounts.ts 상단 주석). 응답에도 절대 내보내지 않는다(017 규칙).

### 탈퇴할 때

탈퇴는 계정 행을 지우지 않고 표시만 한다(`auth-routes.ts` 의 탈퇴 라우트). 그래서 외래키를 연쇄
삭제로 걸어도 피드백은 지워지지 않는다. **탈퇴 라우트의 ③ 단계(개인 기록 삭제)에 피드백 삭제를
직접 넣는다.** 본문과 이메일 모두 개인정보다.

## 3. API

### POST /v1/feedback

`Authorization: Bearer <API_KEY>` 는 다른 `/v1/*` 와 같다. `X-Session-Token` 은 **있으면 붙이고 없어도 된다.**

```json
{
  "category": "place",
  "targetId": "126508",
  "body": "엘리베이터가 공사 중이라 2층에 갈 수 없었어요.",
  "replyEmail": "traveler@example.com",
  "deviceId": "8F3C…",
  "client": {
    "platform": "ios",
    "appVersion": "1.1",
    "build": "160",
    "osVersion": "26.0",
    "model": "iPhone17,1"
  }
}
```

| 필드 | 필수 | 규칙 |
|---|---|---|
| `category` | ✅ | `inquiry` · `place` · `plan` |
| `targetId` | — | `place` 면 contentId(≤64자), `plan` 이면 플랜 uuid. `inquiry` 면 무시 |
| `body` | ✅ | 앞뒤 공백을 뗀 뒤 1~500자 (아래 "글자 수 세는 법") |
| `replyEmail` | — | 이메일 형식, ≤254자. 빈 문자열은 "없음"으로 본다 |
| `deviceId` | — | ≤128자. 로그인 상태여도 보낸다 |
| `client` | — | 객체. 직렬화해서 2KB 이하 |

**201** `{ "id": 123 }` — 앱은 이 값을 화면에 보여 주지 않아도 된다.

| 오류 | 코드 | 언제 |
|---|---|---|
| 400 | `invalid_category` · `invalid_body` · `invalid_email` · `invalid_target` · `invalid_deviceId` · `invalid_client` | 형식이 틀렸다 |
| 401 | `session_expired` | 토큰이 낡았다(다른 라우트와 같다) |
| 429 | `rate_limited` | 너무 자주 보냈다 |

### 글자 수 세는 법

**화면에 보이는 글자 단위로 센다.** 이모지 하나는 1자다.

- 서버: `Intl.Segmenter` (grapheme). 기존 라우트는 `.length` 로 세는데, 그 방식은 이모지를 2자로
  센다. 상한이 2000·5000자인 곳에서는 문제가 없었지만 500자는 빠듯해서 어긋남이 보인다.
- iOS: `String.count` 가 이미 같은 단위다.
- Android: `String.length` 는 서버의 `.length` 와 같은 단위라 **쓰면 안 된다.** `BreakIterator.getCharacterInstance()` 로 센다.

### 요청 횟수 제한

지금의 공통 제한은 API 키 기준이라 앱 설치 전체가 한 버킷을 같이 쓴다. 비로그인도 보낼 수 있으므로
피드백에는 **IP 기준 제한을 따로 둔다** — 10분에 10건. 이동통신망은 여러 사람이 IP 하나를 나눠 쓰는
경우가 많아 너무 빡빡하게 잡지 않았다. 접수된 것만 센다(형식 오류로 거절된 요청은 세지 않는다).

## 4. 앱 화면

### 진입점

| 카테고리 | 화면 | iOS | Android |
|---|---|---|---|
| `inquiry` | 설정 → 고객센터 | `HelpCenterView` 에 "앱에서 의견 보내기" 버튼을 더한다 | **고객센터 화면이 없다.** 새로 만들어야 한다 |
| `place` | 장소 상세 | 상단에 메뉴가 없다(뒤로·지도뿐). **새 진입점이 필요하다** | 더보기 메뉴의 "장소 정보 수정 제안"(지금은 "준비 중" 토스트)에 연결한다 |
| `plan` | 여행 상세 | 상단에 메뉴가 없다(뒤로·멤버·장소 추가·제목 변경). **새 진입점이 필요하다** | "플랜 메뉴"(수정·일정에 추가·삭제)에 "의견 보내기"를 더한다 |

고객센터의 **메일 주소 표시는 그대로 둔다.** 앱스토어 심사(1.2)가 연락 수단 공개를 요구하고,
앱 안 양식이 안 될 때(네트워크 등) 갈 곳이 있어야 한다.

### 화면 구성 — 시트 하나를 세 곳이 같이 쓴다

신고 시트(`ReportSheet`)처럼 시트 하나를 쓰고, 카테고리 줄만 열린 곳에 따라 바뀐다. **제목은 두지 않는다.**

> ⚠️ **로그인을 요구하지 않는다.** `ReportSheet` 는 보내기 전에 `requireSignIn` 을 부른다. 그 시트를
> 본떠 만들면 그 줄이 따라오기 쉽다 — 피드백은 비로그인도 보내야 한다.

위에서 아래로:

1. **카테고리** — 읽기 전용 한 줄. 어디서 열었는지 사용자가 본다. 사용자가 바꿀 수 없다
   - 문의하기: `문의하기`
   - 장소 상세: `장소 상세 · {장소 이름}`
   - 여행 상세: `여행 상세`
   - 장소에 이름을 붙이는 이유: 제목이 없으므로 어느 장소에 대한 의견인지 보여 줄 곳이 이 줄뿐이다
   - 여행 상세는 이름 대신 **플랜 id 를 `targetId` 로 싣는다.** 화면에는 보이지 않는다.
     서버에 저장된 플랜일 때만 싣고, 기기에만 있는 플랜(비로그인)이면 비운다 — 서버가 모르는 id 는
     운영에서 찾을 수 없다. Android 는 `serverId` 가 빈 값인지로, iOS 는 서버 동기화 여부로 가른다
2. **본문 입력** (필수)
   - 카테고리별 안내 문구(placeholder). 예: 장소 상세 → "운영 시간이 달라요, 경사로가 없어요처럼 알려 주세요"
   - 글자 수 표시 `120 / 500`
   - 500자에서 더 입력되지 않게 막는다(`ReportSheet` 와 같은 방식)
3. **답장 받을 이메일** (선택)
   - 이름표에 "(선택)" 을 적는다
   - 로그인 상태면 계정 이메일을 **미리 채운다.** 지울 수 있다
   - 이메일 키보드, 자동 대문자 끔
   - 형식이 틀리면 칸 아래에 오류 한 줄. 비어 있으면 오류가 아니다
   - 안내 한 줄: "답장에만 쓰고, {보관 기간}이 지나면 지워요" — 보관 기간은 아래 §6에서 정한다
4. **정보** — 읽기 전용 한 줄. 피드백과 함께 보내는 기기 정보를 사용자가 본다
   - 실제 값을 그대로 보여 준다. 예: `1.1 (160) · iOS 26.0 · iPhone17,1`
   - 줄 아래에 작게 "이 정보가 함께 전송돼요". 사용자가 모르는 정보가 몰래 가지 않게 한다
   - 화면에 보이는 값과 보내는 `client` 가 같은 값에서 나와야 한다(같은 함수 하나로 만든다)
5. **보내기 버튼** — 하단 고정
   - 본문이 비었거나 공백뿐이면 비활성
   - 보내는 중에는 로딩 표시, 다시 눌러도 한 번만 간다

### 상태별 화면

| 상태 | 보여줄 것 |
|---|---|
| 보내기 성공 | 알림 "보내 주셔서 고마워요" → 확인을 누르면 시트를 닫는다. 이메일을 남겼으면 "답장은 {이메일}로 드릴게요" 를 덧붙인다 |
| 네트워크 실패 | 시트 안에 오류 한 줄. **입력한 내용은 그대로 둔다** — 다시 쓰게 하면 제보를 잃는다 |
| 429 | "잠시 후 다시 보내 주세요" |
| 400 | 해당 칸 아래에 오류(본문·이메일) |
| 401 `session_expired` | 다른 화면과 같은 공통 처리(토큰을 지우고 알림). 그 뒤 **비로그인으로 다시 보낼 수 있어야** 한다 |
| 쓰는 중에 닫기 | 본문이 있으면 "작성한 내용이 사라져요" 확인 |

### 접근성

- 본문·이메일 칸에 음성 이름표를 단다("의견 내용", "답장 받을 이메일, 선택")
- 카테고리·정보 줄은 버튼이 아니라 글로 읽힌다("카테고리, 장소 상세, 경복궁"). 누를 수 있는 것처럼 보이게 하지 않는다
- 글자 수는 매 글자 읽지 않는다. 칸의 값으로 "500자 중 120자" 를 싣고, 450자를 넘으면 한 번 알린다
- 보내기 버튼이 비활성일 때 이유를 힌트로 준다("내용을 입력하면 보낼 수 있어요")
- 오류와 성공은 화면을 보지 않는 사용자에게도 읽히게 한다(`ReportSheet` 의 오류 줄과 같은 처리)
- 글자 크기 키우기에서 칸과 버튼이 잘리지 않는다

### 앱이 모으는 기기 정보

| 키 | iOS | Android |
|---|---|---|
| `platform` | `"ios"` | `"android"` |
| `appVersion` | `CFBundleShortVersionString` | `BuildConfig.VERSION_NAME` |
| `build` | `CFBundleVersion` | `BuildConfig.VERSION_CODE` |
| `osVersion` | `UIDevice.current.systemVersion` | `Build.VERSION.RELEASE` |
| `model` | `utsname().machine` (예: `iPhone17,1`) | `Build.MANUFACTURER` + `Build.MODEL` |

- iOS 는 버전·빌드·OS 를 읽는 코드가 `HelpCenterView` 에 이미 있다. 공통 함수로 빼서 같이 쓴다.
- Android 의 `versionName = "1.0"` / `versionCode = 1` 은 처음 값 그대로다. **릴리스마다 올려야** 버전이 구분된다.

## 5. 운영 화면 (대시보드)

신고 운영(049) 옆에 피드백 목록을 둔다.

- **목록:** 접수 시각 · 카테고리 · 대상 · 본문 앞부분 · 이메일 유무 · 상태 · 앱 버전/OS/기종 · 로그인 여부(닉네임)
- **대상 표시:** 장소는 이름과 링크(공개 정보). 플랜은 id 만 — 플랜은 멤버만 보는 개인 데이터다
- **필터:** 상태, 카테고리
- **상세:** 본문 전체, 이메일(복사·메일로 답장), "이 기기·계정에서 온 다른 피드백 N건" — `device_id` 값 자체는 보여 주지 않는다
- **상태 바꾸기:** `new` → `answered` → `closed`
- **Apple 가리기 주소 표시:** 이메일이 `@privaterelay.appleid.com` 이면 표시를 단다. Apple 개발자 계정에 보내는 쪽 도메인(`moduwa.app`)을 등록하지 않으면 `help@moduwa.app` 에서 보낸 답장이 반송된다

## 6. 정할 것

1. ~~보관 기간~~ → **접수 후 1년**으로 정했다. 서버가 하루 한 번 지운다(`feedback.ts` 의 `purgeExpiredFeedback`).
   처리방침 4항에 들어갔다. 이메일 칸 안내 문구의 `{보관 기간}` 은 "1년" 이다
2. **iOS 장소·여행 상세의 진입점 위치.** 두 화면 모두 지금은 메뉴가 없다
3. **접수 알림.** 피드백이 들어오면 운영자에게 메일(Resend)로 알릴지
