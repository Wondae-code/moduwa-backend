# 소셜 로그인과 기존 계정 연결 — 앱 개발자용 안내

같은 이메일로 이메일 가입과 소셜 로그인(구글·애플·카카오)이 섞일 때 서버가 어떻게 동작하고,
앱이 무엇을 처리해야 하는지 정리한 문서다. 로그인 API 전체는 `docs/API.md` 를 본다.

## 1. 배경

DB 에는 "이메일 하나에 계정 하나" 규칙이 있다. 한 사람의 후기·플랜이 두 계정으로 갈리는 것을
막기 위해서다. 그런데 이메일로 가입한 사람이 같은 주소의 소셜로 로그인하면 새 계정을 만들다
이 규칙에 걸렸다. 지금은 그런 경우 서버가 **기존 계정에 소셜 로그인을 이어 붙이거나**, 붙일 수
없으면 **앱이 사용자에게 묻게** 한다.

## 2. 원칙

- 계정의 키는 이메일이 아니라 **`(provider, subject)`** 다. 이메일은 바뀔 수 있다.
- 이메일은 "기존 계정에 붙일 근거"로만 쓴다. 그 근거는 **프로바이더가 이메일 소유를 확인해
  줬을 때만**(`email_verified`) 인정한다. 구글·애플은 확인해 주고, 카카오는 확인해 주지 않는다.
- 확인이 없으면 자동으로 붙이지 않는다. 카카오는 사용자에게 묻고, 이메일 가입은 거부한다.
- 이미 다른 계정에 붙은 소셜 계정은 **합치지 않는다.** 병합은 후기·플랜 소유자를 옮기는 일이라
  별도 설계가 필요하다.

## 3. 경로별 동작

| 순서 | 서버 동작 | 응답 |
|---|---|---|
| 이메일 가입 → 같은 주소로 **구글·애플** 로그인 | 기존 계정에 자동 연결. 글·플랜·프로필 유지 | 200, `linked: true` |
| 위와 같은데 기존 계정이 **이메일 인증 전** | 자동 연결하되 이메일 비밀번호를 지우고 모든 세션을 끊음. 그 주소로 알림 메일 발송 | 200, `linked: true, passwordReset: true` |
| 이메일 가입 → 같은 주소로 **카카오** 로그인 | 자동 연결 안 함. 계정도 안 만듦. 앱이 묻는다 | 409 `link_required` + `providers` |
| 카카오 409 에서 **기존 계정에 연결** | 기존 방식으로 로그인한 뒤 카카오 토큰을 연결 API 로 | `POST /v1/auth/me/identities` → 200 |
| 카카오 409 에서 **새 계정으로 시작** | 별도 계정 생성. 대표 이메일은 비움 | `newAccount: true` 로 재요청 → 201 |
| 소셜 먼저 → 같은 주소로 **이메일 가입** | 거부. 소셜 계정에 비밀번호를 붙여 주지 않음 | 409 `email_taken` + `providers` |
| 애플 **이메일 가리기**(릴레이 주소) | 주소가 달라 자동 연결 대상 아님. 별도 계정 | 201 |
| 같은 토큰으로 요청이 겹침 | 두 번째는 재시도하면 정상 로그인 | 409 `conflict` |

## 4. 왜 이렇게 나눴나

**구글·애플은 자동, 카카오는 질문.** 구글·애플 ID 토큰에는 `email_verified` 가 있고 카카오
토큰에는 없다. 검증 안 된 이메일로 붙이면, 카카오 계정에 남의 주소를 넣어 두는 것만으로 그
사람의 모두와 계정을 가져갈 수 있다. 그렇다고 말없이 별도 계정을 만들면 사용자는 후기·플랜이
빈 계정을 보게 된다. 그래서 카카오는 로그인 순간에 한 번 묻는다.

**인증 전 계정은 비밀번호를 지운다.** 남의 주소로 이메일 가입만 해 두고(인증 메일은 못 받으니
인증은 못 한다) 비밀번호를 쥔 채 기다리는 선점 탈취 패턴이 있다. 주소의 진짜 주인이 구글로
들어오는 순간 그 비밀번호를 무효화하면 선점한 쪽은 잘리고, 진짜 주인은 구글로 쓰거나 비밀번호
찾기(그 주소로 코드가 간다)로 복구된다. 같은 시점에 그 주소로 알림 메일도 간다 — 앱 화면은
방금 소셜로 들어온 사람만 보기 때문이다.

**이메일 가입 쪽으로는 절대 붙이지 않는다.** 이메일 소유를 증명하지 않은 사람이 남의 소셜 계정에
비밀번호를 만들어 넣는 셈이 된다. 409 에 `providers` 를 실어 "구글로 로그인해주세요"로 안내한다.

**설정의 "연결된 계정" 화면은 두지 않는다.** 실제 구멍은 카카오 하나였고, 그건 로그인 순간의
다이얼로그로 막힌다. 서버에는 목록·연결·해제 API 가 있으니 화면이 필요해지면 그때 얹는다.

## 5. 앱이 처리할 것

### ① 소셜 로그인 응답의 `linked` · `passwordReset`

```json
{ "token": "...", "expiresAt": "...", "author": { ... },
  "created": false, "linked": true, "passwordReset": false }
```

- `linked: true` — 기존 계정에 연결된 것이다. `created` 와 동시에 true 가 되지 않는다.
  온보딩을 띄우지 말고 "기존 계정에 연결했어요. 글과 플랜은 그대로예요." 를 한 번 알린다.
  요청에 실은 `accessFeatures`·`nickname` 은 무시되고 기존 계정 값이 유지된다.
- `passwordReset: true` — 연결하면서 이메일 비밀번호가 지워졌다. "이메일 비밀번호는 지워졌어요.
  '비밀번호 찾기'로 다시 설정해 주세요." 를 덧붙인다. 구글 로그인은 그대로 된다.
- 이메일 가입·로그인 응답에도 같은 필드가 오지만 항상 `false` 다.

### ② 이메일 가입 409 `email_taken` 의 `providers`

```json
{ "error": "email_taken",
  "message": "구글 로그인으로 가입된 이메일입니다. 그 방식으로 로그인해주세요.",
  "providers": ["google"] }
```

- `providers` 에 `"email"` 이 있으면 이메일 로그인으로 안내한다.
- `"email"` 이 없고 소셜만 있으면 **그 소셜 버튼으로** 안내한다. 이 사용자는 비밀번호가 없어서
  이메일 로그인이 항상 실패한다. `message` 를 그대로 띄워도 된다.
- 빈 배열이면 종전 문구("이미 가입된 이메일입니다")로 둔다.

### ③ 카카오 로그인 409 `link_required` — 다이얼로그 하나

카카오 로그인을 제공하는 앱만 해당한다.

```json
{ "error": "link_required",
  "message": "이 이메일로 가입된 계정이 있습니다(이메일 로그인). 기존 계정에 연결하거나 새 계정으로 시작할 수 있습니다.",
  "providers": ["email"] }
```

이 시점에 서버에는 아무것도 만들어지지 않았다. **카카오 `idToken` 은 버리지 말고 들고 있는다.**

| 선택 | 앱이 할 일 |
|---|---|
| 기존 계정에 연결 | `providers` 의 방식으로 로그인한다(이메일이면 비밀번호 입력, 구글이면 구글 버튼). 세션을 얻은 뒤 들고 있던 카카오 토큰을 `POST /v1/auth/me/identities` 에 `{ "provider": "kakao", "idToken": "..." }` 으로 보낸다. 이후 카카오로 바로 로그인된다 |
| 새 계정으로 시작 | 같은 카카오 로그인 요청에 `"newAccount": true` 를 붙여 다시 보낸다. 201 이 오고 별도 계정이 생긴다. 그 계정의 `email` 은 `null` 로 시작한다 |
| 취소 | 아무것도 하지 않는다 |

`POST /v1/auth/me/identities` 의 응답과 오류:

- 200 `{ linked: true, identities, author }`. 같은 카카오 계정을 다시 붙이면 오류가 아니라 `alreadyLinked: true`.
- 409 `identity_in_use` — 그 카카오 계정이 이미 **다른** 모두와 계정에 붙어 있다. 합치지 않는다.
  "그 계정으로 로그인해주세요" 로 안내한다.
- 409 `provider_already_linked` — 이 계정에 카카오가 이미 붙어 있다. 정상 흐름에서는 나오지 않는다.
- 401 `invalid_token` — 카카오 토큰이 만료됐거나 잘못됐다. 카카오 로그인부터 다시 한다.

`newAccount` 는 409 를 받은 뒤에만 의미가 있다. 평소 요청에 붙여도 무시되고, 구글·애플에는
영향이 없다.

### ④ 409 `conflict`

같은 토큰으로 요청이 겹쳤을 때다. 연타를 막고 있고 자동 재시도가 없다면 따로 처리하지 않아도
된다. 처리한다면 "다시 시도해주세요" 면 충분하다.

## 6. 서버 API 요약

| 엔드포인트 | 내용 |
|---|---|
| `POST /v1/auth/google` · `/apple` · `/kakao` | 응답에 `linked`, `passwordReset`. 요청에 `newAccount`(카카오 409 이후에만 의미). 오류 409 `link_required` · `conflict` |
| `POST /v1/auth/email/sign-up` | 409 `email_taken` 에 `providers`. 소셜 계정의 대표 주소까지 중복 검사 |
| `GET /v1/auth/me/identities` 🔒 | 이 계정에 붙은 로그인 방식 목록 `[{provider, email, linkedAt}]` |
| `POST /v1/auth/me/identities` 🔒 | `{provider, idToken, authorizationCode?}` 로 붙이기. 프로바이더당 하나. 409 `identity_in_use` · `provider_already_linked` |
| `DELETE /v1/auth/me/identities/:provider` 🔒 | 떼기. 마지막 하나는 409 `last_identity`. 애플은 토큰도 폐기 |

🔒 는 `x-session-token` 이 필요한 엔드포인트다. 응답 예시와 오류표 전체는 `docs/API.md` 의
"같은 이메일, 다른 로그인 방식", "카카오 — `link_required`", "연결된 계정" 절에 있다.

## 7. 애플 로그인 관련

- 자동 연결은 애플에도 같게 적용된다. 애플이 `email_verified` 를 문자열 `"true"` 로 주는 것까지
  서버가 처리한다.
- "이메일 가리기"를 켠 사용자는 릴레이 주소라 기존 계정과 자동으로 이어지지 않고 별도 계정이 된다.
- 애플 로그인 요청에는 `idToken` 외에 `nickname`(최초 인증 응답의 이름)과 `authorizationCode`
  (계정 삭제·연결 해제 때 애플 쪽 토큰 폐기용)를 함께 보낸다.
